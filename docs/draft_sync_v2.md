# 三小时长条草稿与语音（2026-09-09）

本文件取代旧 `ime_draft_sync_api.md`（现移动为 `交接文档ime_draft_sync_api.md`）中的新增记录游标协议。README / DESIGN 的日报统计与离线 ASR 是早期规划，不代表当前实现。

## 分段与保留

- 同一个 App 内，键盘活动间隔小于 5 分钟，已提交文字追加到同一条；标点、发送、换行和同 App 内重开键盘不主动分段。
- 间隔达到 5 分钟，或 Android 通知输入法当前编辑器属于另一 App，下一次提交新建记录。未上屏的拼音按键也算活动。
- 密码、邮箱等敏感输入框禁止记录，并打断前后草稿会话；语音也不在敏感输入框启动。
- 进程重启后新起一条。完全没有输入框的 App 切换未必通知 IME，因此无法保证捕获这种短暂离开。
- 三小时按最后追加时间 `updated_at` 计算：连续长条不会因超过三小时而从中间切断，停止追加三小时后整条到期。运行期间每分钟清理，读取或回传时也清理；进程停止时不会运行后台清理。
- 内容是按提交顺序拼接的输入历史，保留空格/换行；不是聊天记录或应用最终文稿的镜像，退格、选区替换、移动光标不会回头修改历史。
- 系统复制/剪切/粘贴和键盘剪贴板面板粘贴不入池。
- 仅 ASCII / 全角阿拉伯数字替换为 `*`，其他文字（包括中文数字）保留。这是数字遮蔽，不是完整匿名化。本轮按用户明确需求继续提供三小时草稿及可选电脑回传，不将其混入行为统计或用户词库。

## 当前回传格式

手机主动向设置中的完整 HTTPS URL 发 HTTP POST；不是电脑拉取，也不是 WebSocket。不包含音频。

```http
POST /v1/ime/drafts HTTP/1.1
Authorization: Bearer <配对密钥>
Content-Type: application/json
```

JSON 数组示例（虚构数据）：

```json
[
  {
    "id": 123,
    "created_at": 1788919200000,
    "updated_at": 1788919380000,
    "revision": 8,
    "app_package": "com.tencent.mm",
    "source": "mixed",
    "content": "今天想整理项目思路。\n先处理界面，再补*个测试。最后这句话是语音补充的。"
  }
]
```

| 字段 | 含义 |
|---|---|
| `id` | 手机本地记录 ID；同一长条持续追加时不变 |
| `created_at` | 首次提交时间，Unix 毫秒 |
| `updated_at` | 最后追加时间，Unix 毫秒；用于展示和过期 |
| `revision` | 该记录的版本，从 1 开始，每次追加加 1 |
| `app_package` | 来源编辑器包名 |
| `source` | `keyboard`、`voice` 或两者混用的 `mixed` |
| `content` | 本版本完整文本，不是新增尾巴；JSON 中换行写作 `\n` |

手机每分钟检查发送时机，按配置间隔（默认 15 分钟）发送尚未确认的新记录或更新版本；需要 IME 进程存活，不是保证准点的后台任务。失败后下次间隔重试；已到期草稿不补传。上报默认关闭，本轮没有替用户打开或实际回传数据。

服务端必须：

1. 用 Bearer token 确定设备身份。请求体没有 `device_id`，设备 ID 由服务端认证上下文得到；重装/清除手机数据后重新配对新的设备身份，防止本地 ID 重用。
2. 按 `(device_id, id)` **upsert**：只有更大的 `revision` 才替换整条文本；相同/较小版本幂等忽略。不能只按 ID 去重后丢弃更新，也不能把 `content` 再次追加到旧文本后面。
3. 整批持久化后返回任意 `2xx`（建议 `204`）。失败返回非 `2xx`，客户端保留该版本待重试。上传期间手机继续追加的新版本会留给下一轮。
4. 不打印请求内容到访问日志/异常追踪。手机清空不发删除指令；电脑端保留和清理独立执行，可按 `updated_at` 实现三小时过期。

旧接收端需要增加 `updated_at`、`revision`、`mixed` 并改为版本覆盖；否则长条后续追加会丢失。电脑收到后，可直接取 `content` 作为一个 LLM 输入，也可按换行/标点分段；手机不会自动调用 LLM。本仓库未实现或验证电脑接收端。

## 语音的实际状态

当前使用 Android `SpeechRecognizer`，不是内置 sherpa-onnx，也没有 PC 音频推流；是否联网、可用语言及识别质量由手机系统语音服务决定。

长按空格打开键盘内面板：启动 → 麦克风就绪 → 真实 RMS 音量条及 partial 文字 → 完成/自动结束 → final 上屏。取消、收起键盘、切换输入框会销毁识别器并忽略迟到结果。无服务、缺权限、网络失败和超时都有可见提示。音量回调由系统提供，未提供 RMS 的服务不能显示有效音量变化。

final 只有在成功提交到非敏感输入框时才记录一次，和同 App 的键盘输入共用长条，混合来源标为 `mixed`。partial 不入池、不回传，音频不由本项目保存。
